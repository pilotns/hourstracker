# hourstracker

Мобильное веб-приложение для учёта рабочих часов Amazon Flex. JavaScript + Vite; статическая сборка для GitHub Pages, регистрация и история между устройствами через Supabase.

## Как пользоваться

- Главный экран показывает сумму за **7 календарных дней включительно**: выбранная конечная дата и шесть дней перед ней. Например, для 11 октября окно — с 5 по 11 октября. Это скользящее окно, а не календарная неделя. При открытии приложения окно заканчивается завтра: сегодня — предпоследний день, перед ним пять прошлых дней.
- В центре круга на Overview показаны доступные часы: **40 часов минус отработанные и зарезервированные часы** в выбранном окне. Оранжевая дуга и процент показывают использованную долю лимита; заполнение плавно меняется при изменении данных или окна. Лимит фиксирован. При превышении круг полностью заполнен, доступно 0 часов, а процент превышает 100%. Сразу под кругом расположены семь дней.
- Стрелки и горизонтальный свайп сдвигают окно на один день. Поле даты позволяет выбрать конец семидневного окна.
- Интерфейс по умолчанию на английском. В шапке можно выбрать украинский; выбор сохраняется в этом браузере.
- Нажмите на день, чтобы добавить или изменить рабочее время. Значения хранятся в минутах, поэтому сумма не накапливает ошибки округления.
- В редакторе дня укажите общее число минут или нажимайте кнопки **+90, +120, +240, +480**. Каждое нажатие добавляет минуты, включая повторные нажатия одной кнопки: +90, +90 → 180 минут. Кнопки добавляют время к сохранённой или введённой вручную сумме. Максимум за день — 1440 минут; для уменьшения измените сумму вручную.
- Можно выбирать будущие даты и сохранять зарезервированные блоки. В редакторе остаётся только длительность; ранее сохранённые заметки не удаляются при изменении минут.
- Сумма за 7 дней включает отработанные и зарезервированные часы; раздельные итоги доступны на History. При сохранении будущие даты получают статус `Reserved`, сегодняшние и прошлые — `Completed`. Чтобы отметить ранее забронированный день отработанным, откройте его и сохраните длительность после наступления этой даты.
- История включает будущие бронирования. Доступны фильтр по месяцу и экспорт CSV со статусом каждой записи.
- Без настройки Supabase доступен гостевой режим: история сохраняется в браузере на этом устройстве. Очистка данных браузера удалит её.
- После подключения Supabase можно зарегистрироваться по email, войти и хранить историю в своём аккаунте.

Приложение ведёт самостоятельный учёт часов и не подключается к аккаунту Amazon Flex.

## Локальный запуск

Требуется Node.js 22.12+ и npm.

```sh
npm install
cp .env.example .env.local
npm run dev
```

С пустыми переменными в `.env.local` приложение работает в гостевом режиме. После изменения переменных перезапустите сервер разработки.

```sh
npm test
npm run build
npm run preview
```

Сборка находится в `dist/`. Vite использует относительный `base: './'`, поэтому ресурсы работают и в корне домена, и по пути репозитория GitHub Pages.

## Подключение Supabase

1. Создайте проект Supabase. В **SQL Editor** выполните [supabase/schema.sql](supabase/schema.sql). Схема включает правила Row Level Security: пользователь имеет доступ только к своим записям.

   Если схема уже применялась до добавления бронирований, выполните её повторно: она добавит поле `status`, сохранив существующие записи как `completed`. Старые локальные записи также читаются без потери данных.
2. В настройках проекта или диалоге **Connect** скопируйте Project URL и **publishable key** в `.env.local`:

   ```dotenv
   VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_KEY
   ```

   Эти значения входят в код, отправляемый в браузер. Используйте только публичный publishable key; `service_role` и `sb_secret_…` сюда помещать нельзя. Доступ к данным защищают Auth и правила RLS. [Документация ключей Supabase](https://supabase.com/docs/guides/getting-started/api-keys).

3. В **Authentication → Sign In / Providers → Email** включите регистрацию по email и подтверждение адреса. В **Authentication → URL Configuration** задайте **Site URL** равным конечному URL приложения, например `https://YOUR_USERNAME.github.io/YOUR_REPOSITORY/`.
4. В **Redirect URLs** добавьте точный URL сайта с путём репозитория и завершающим `/`, а для разработки — `http://127.0.0.1:5173/` (и `http://localhost:5173/`, если открываете сайт по этому адресу). При использовании `npm run preview` добавьте также `http://127.0.0.1:4173/`; если Vite выбрал другой порт, добавьте фактический адрес. Подтверждение email и восстановление пароля возвращают пользователя в приложение по этому адресу. [Настройка redirect URL](https://supabase.com/docs/guides/auth/redirect-urls).
5. Оставьте стандартные шаблоны писем с `{{ .ConfirmationURL }}`. Если шаблоны уже изменены, проверьте, что ссылки учитывают переданный redirect URL, включая путь репозитория. [Шаблоны писем Supabase](https://supabase.com/docs/guides/auth/auth-email-templates).
6. Перезапустите `npm run dev` и проверьте регистрацию, подтверждение email, вход, сохранение дня и восстановление пароля на своём проекте.

Локальное подключение настроено через `.env.local`. Проверка Auth API подтвердила, что ключ принимается, регистрация по email разрешена и требуется подтверждение адреса. После выполнения SQL таблица `public.work_entries` существует: запрос без входа возвращает ожидаемый отказ `42501` (`permission denied`), поскольку схема запрещает доступ роли `anon`. Выдавать этой роли доступ к таблице не нужно. Пользователь подтвердил работу регистрации в локальном приложении. Сохранение записи под аккаунтом отдельно не проверено. При публикации добавьте новый URL сайта в Site URL и Redirect URLs. Публичный ключ не даёт прав на создание таблиц или изменение настроек проекта. Для публичного использования настройте доставку писем в Supabase согласно [руководству по SMTP](https://supabase.com/docs/guides/auth/auth-smtp).

## Публикация на GitHub Pages

1. Создайте репозиторий и загрузите содержимое этой папки в его корень, включая `package-lock.json` и `.github/workflows/deploy.yml`. Workflow запускается при push в `main`; при другом имени ветки измените `branches`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Для облачного режима в **Settings → Secrets and variables → Actions → Variables** добавьте repository variables `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` с теми же значениями, что локально. Без них публикуется гостевой режим. `.env.local` в репозиторий не загружайте.
4. Отправьте изменения в `main` или запустите **Actions → Deploy to GitHub Pages → Run workflow**. Workflow установит зависимости, выполнит тесты, соберёт `dist/` и опубликует его. Готовый URL появится в результате deployment и в **Settings → Pages**.
5. Внесите этот точный URL в настройки Supabase из предыдущего раздела. После изменения repository variables снова запустите workflow: Vite подставляет значения во время сборки.

Репозиторий и сайт не создаются автоматически при локальном запуске. Схема публикации использует официальные [GitHub Pages Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
